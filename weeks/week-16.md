## 第 16 週：期末成果展與除錯競賽

### 📌 學習目標
- 訓練學生在有限時間內清楚表達技術成果與情境設計理念。
- 透過同儕互評與教師提問，強化系統思維的批判性檢視能力。
- 透過除錯競賽，鞏固整學期學會的除錯能力。
- 建立與未來課程（AIoT 移動載具、智慧製造）的銜接概念。

### 🕐 第 1 小時：小組實機 Live Demo

**流程建議**：
1. 各組上台展示 Tinkercad 專案（5 分鐘展示 + 3 分鐘提問）。
2. 展示內容須包含：情境說明、硬體佈局簡介、核心邏輯講解、實機操作演示。
3. 教師與同學進行「刁難測試」，範例提問：
   - 「如果同時觸發你設計的兩個異常條件，系統會怎麼反應？」
   - 「連續觸發警報後，能不能順利解除？」
   - 「如果我把感測器數值拉到最大/最小極限，系統會不會當機？」
4. 評分項目建議：**功能完整性（30%）、情境合理性（20%）、程式碼可讀性（20%）、應變測試表現（20%）、口頭表達（10%）**

### 🕑 第 2 小時：實境除錯大挑戰（Debug Challenge）

教師可預先準備以下三類「有問題的程式碼／電路」，讓學生分組搶答修正，増加課程趣味性與總結複習效果。

#### 挑戰 1：語法除錯範例
```cpp
// ============================================
// 挑戰：這段程式碼有 3 個語法錯誤，請找出並修正
// ============================================

int pinLed = 13

void setup() {
  pinMode(pinLed, OUTPUT);
}

void loop() {
  digitalWrite(pinLed, HIGH)
  delay(500);
  digitalWrite(pinLed, LOW);
  delay(500);
}

/* 提示（答案，教師自行決定是否先隱藏）：
   1. 第 2 行結尾少了分號 int pinLed = 13;
   2. loop() 內 digitalWrite(pinLed, HIGH) 少了分號
   3. （可視教學需求再自行安插第三個錯誤，例如少一個大括號）
*/
```

#### 挑戰 2：硬體除錯範例
> 提供以下電路情境卡片，讓學生口頭或實際在 Tinkercad 上找出問題：
> - **情境 A**：LED 接上電後完全不亮。（常見原因：LED 長短腳接反、電阻接錯位置導致短路、忘記接 GND）
> - **情境 B**：按鈕怎麼按 Serial Monitor 數值都不會變。（常見原因：忘記加下拉電阻導致腳位懸空、`pinMode` 忘記設為 `INPUT`）
> - **情境 C**：伺服馬達完全沒有反應。（常見原因：忘記呼叫 `.attach()`、電源沒有接 5V、訊號線接錯腳位）

#### 挑戰 3：邏輯除錯範例
```cpp
// ============================================
// 挑戰：這段程式碼會導致 LED 永遠不會熄滅，請找出邏輯問題
// ============================================

int pinButton = 7;
int pinLed = 13;
bool machineOn = false;

void setup() {
  pinMode(pinButton, INPUT);
  pinMode(pinLed, OUTPUT);
}

void loop() {
  if (digitalRead(pinButton) == HIGH) {
    machineOn = !machineOn;   // 錯誤：這裡沒有偵測「按下瞬間」，只要按著就會瘋狂切換
  }
  digitalWrite(pinLed, machineOn ? HIGH : LOW);
}

/* 提示：正確寫法需要加入 lastButtonState 變數，
   只在「currentState == HIGH && lastButtonState == LOW」的瞬間才切換狀態，
   這正是第 2 週實作 4 教過的 Toggle 邏輯，可藉此檢視學生是否真正內化該觀念。
*/
```

### 🕒 第 3 小時：從虛擬到實體與課程總結

**教師實機示範**：現場準備一組實體 Arduino 套件，將前幾名學生設計的程式碼直接燒錄進真實硬體，展示「模擬環境」與「真實世界」的一致性，這一刻通常是整學期最具震撼效果的教學亮點，能讓學生體會到「我在螢幕上寫的程式碼，真的能操控真實世界的物品」。

**銜接未來課程討論**：
- 這學期學到的**感測 → 判斷 → 動作**邏輯架構，正是「AIoT 移動載具」與「智慧製造」的基礎骨架。
- Wi-Fi 連網（如 ESP32、Arduino IoT Cloud）能讓這學期做的系統上傳資料到雲端，實現遠端監控。
- 多顆感測器的資料，未來可以餵給簡易的機器學習模型，做出「異常預測」而非單純的「門檻判斷」。

**課程總結與心得分享**：
- 請每位學生用 3 句話寫下：「這學期我做出的最有成就感的一個功能」、「我認為工業管理系學習寫程式的價值是什麼」、「如果重來一次，我會想先學會哪個元件」。
